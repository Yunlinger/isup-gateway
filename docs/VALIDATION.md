# 验证记录与适用范围

2026-10-06 在用户授权环境验证，服务端 SDK 为 `2.5.1.35`（2024-11-01）。
本文件不包含真实地址、设备身份、登录信息、SDK 二进制、抓包或监控画面。

## 协议证据

- 自行计算的四步认证签名与真实摄像头抓包逐字节匹配。
- 使用新设备 ID 完成认证、SessionKey 交换、DAS 重定向及 MQTT 上线。
- 标准 AES-CBC 实现通过 NIST SP 800-38A 已知向量。
- 独立还原真实摄像头 HEVC RTP，成功解码 178 帧，704×576。
- 视频文件虚拟设备经隔离服务端 SDK 接收、输出 PS，并独立解码 304 帧。
- 关闭 x265 信息 SEI 后，解决该 SDK 首 1024 字节内无法识别首帧的问题。

## 实时网关证据

- 真实摄像头接入源平台，网关以新设备身份向另一服务器的 ISUP 平台注册。
- 目标 CMS 发起预览，SMS SDK 持续回调，目标平台实际显示当前摄像头画面。
- 目标输出的录制文件独立解码 136 帧 H.264，704×576，时长 5.44 秒。
- 两个独立虚拟设备会话各收到 1830 帧，源订阅数为 2、累计编码器启动次数为 1。
- 停一路后另一路继续出帧；停最后一路后源关闭，两设备注册继续在线。
- 测试后移除临时第二设备，恢复正式目标并重新预览成功。

这些证据验证一个目标平台及同平台上的双会话共享源。三个不同客户平台尚需
分别联调，不能仅因都称为 ISUP 就保证全部兼容。

## 公开自动测试

无需网络、真实设备、SDK 或凭据，执行：

```bash
python -m unittest discover -s tests -v
```

覆盖 AES 已知向量、MQTT 分片和长度、业务边界、HEVC FU 丢包和序号回绕、
RTP 扩展与截断、Annex B 跨读取边界、慢目标关键帧恢复、配置身份校验、
共享源的停止与重启。真实抓包回归仍保留在本地研究目录，不随仓库发布。
